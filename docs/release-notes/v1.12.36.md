# v1.12.36

批处理发送路径收紧的一版：flush 间隔固定为 1ms，写 deadline 提到 `Send` 入口统一装，`Options` 不再带 interval 字段。**写失败的错误码有变化**，见「行为变化」。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/client.go` `Options` | 删掉 `flushInterval` 字段，`DefaultOptions` 不再填；间隔固定为 `defaultFlushInterval`（1ms），`WithBufSize` 只决定批处理的字节阈值，不再影响 flush 频率 |
| `transport/channel.go` `Send` | `SetWriteDeadline` 提到函数开头：批处理路径（`n < bufsize` 后 `return nil`）也装 deadline，timer flush 写的是这一批刚装上来的新鲜值，不再继承上一次 `Send` 留下的旧值 |
| `transport/channel.go` `newChannel` 的 `push` | 不再自装 deadline；写失败仍然只记 `slog.Debug` |
| 注释 | `Send` 两条路径的 deadline 归属与错误归属、`push` 的失败只记日志、`WithBufSize` 的间隔不可配、`Keepalive()` 是固定 10s 而不是 `defaultTimeout` 的倍数、`defaultFlushInterval` 是唯一取值 |

## 行为变化：写失败的错误码

`Send` 的两种写失败现在都返回**原始 I/O 错误**，不再包 `codes.Unavailable`：

- `SetWriteDeadline` 失败：只有本地连接已经 `Close` 时才会发生（对端断开不会触发，它只写本地 deadline 字段），错误是 `use of closed network connection`
- `WriteTo` 失败：写超时是 `i/o timeout`；对端断开在 Windows 上是 `wsasend: An established connection was aborted by the software in your host machine`，Linux 上是 `write: connection reset by peer`。首次写通常仍成功，因为字节进了内核发送缓冲，要等 RST 或写满窗口才暴露

这两类错误都不实现 `GRPCStatus`，`stream.go` 的 `sender.send` 又是原样透传，所以 `status.Code(err)` 落到 `codes.Unknown`——调用方拿不到「帧没写完、对端没执行、可重试」这个信号。
