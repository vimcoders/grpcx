# v1.12.37

写失败处置收紧的一版：`Send` 与 timer flush 一旦写失败就立刻关闭连接，不再把坏连接留给下一次调用去发现。对外签名不变，错误码没变。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/channel.go` `Send` 的 `SetWriteDeadline` | 失败时 `errors.Join(err, ch.Conn.Close())` 返回，连接一并关闭 |
| `transport/channel.go` `Send` 的 `WriteTo` | 失败时 `errors.Join(err, ch.Conn.Close())` 返回，连接一并关闭 |
| `transport/channel.go` `newChannel` 的 `push` | timer flush 失败时关闭连接，I/O 错误与 Close 结果一起 join 后记 `slog.Debug` |

## 行为变化

- 写失败会立即关连接。此前是「错误返回、连接留在原地，等下一次调用自己发现」，现在当次就把连接废掉。
- 批处理缓冲不主动清空：连接已经关闭，下一次 `Send` 会在自己的 `SetWriteDeadline` 上直接失败，残留的半帧没有机会被写进新调用。
- 错误码没有变化：`errors.Join` 里只有 I/O 错误和 Close 结果，两者都不实现 `GRPCStatus`，`status.Code` 仍是 `codes.Unknown`。
