# v1.12.38

失败语义收口的一版：写失败、连接断开、`Close`、流超时四条路对外统一报 `codes.Unavailable`，关闭传输时在途调用立刻醒来，不再等满自己的流超时。P1-1 与 P1-3 清零，P1-2 仍未处理完——攒批模式下 timer flush 失败只记日志。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/channel.go` `Send` 的两处失败返回 | 在 `errors.Join` 里补上 `status.Unavailable`，`SetWriteDeadline` 与 `WriteTo` 失败不再落到 `codes.Unknown` |
| `transport/client.go` `Close` | 持锁遍历 `streams`，逐条 `s.Close()`（cancel 流上下文），`clear` 表，再置 `maxStreams = 0`，最后关连接 |
| `transport/client.go` `createStream` | 签名收为 `_ ...CallOption`；流上下文改用 `c.readTimeout` |
| `transport/stream.go` `recv` | `ctx.Done()` → `Unavailable`；接收槽关闭 → `Canceled`（今天无人触发，仅作兜底） |

## 行为变化

- **写失败一律 `Unavailable`**：此前 `Send` 只 join I/O 错误和 Close 结果，`status.Code` 落到 `codes.Unknown`，调用方拿不到「帧没写完、对端可能没执行」的信号。
- **关闭立刻唤醒在途调用**：`Close` 现在取消每一条在途流的上下文，等待应答的 `RecvMsg` 马上返回 `Unavailable`；此前它要等到自己的流超时，默认 3s，上下文更长时更久。
- **流超时跟随 `WithReadTimeout`**：`createStream` 不再读 `Options.timeout` 或 `CallOption` 里的 Timeout，改用 `readTimeout`（默认 30s，即 3 个 keepalive）。`WithTimeout` 与 `Options.Timeout()` 保留 API，但请求路径不再消费它们。
- **自己取消也报 `Unavailable`**：调用方 cancel 自己的 ctx、deadline 到期、`Close` 取消、连接断开，四条出口现在同一个码。这与 gRPC 惯例（调用方取消报 `Canceled`）相反，按码分流的上层要按 `Unavailable` 处理「可能未执行」，不能当作可立即重放。

## 测试

- 门禁全绿：`gofmt -l .` 空、`go vet ./...` 空、`golangci-lint run` 0 issues、`go test ./... -count=1` 151 通过 0 失败（Windows，`CGO_ENABLED=0`）。
- 云主机补跑竞态：`go test -race ./...` 全包通过，`go test -race ./transport -count=5` 通过（Ubuntu 22.04.5，Go 1.23.0 + `GOTOOLCHAIN=auto`）。
- 用例按新语义重写：`TestChannelSendReportsWriteFailure`、`TestChannelSendMapsAWriteFailureToUnavailable` 断言 `Unavailable`；`TestCloseClosesTheConnectionOnceAndRefusesNewStreams` 断言上下文被取消、流表被清空；`TestCloseWakesAnInFlightCall` 断言立即唤醒；`TestCreateStreamDeadlineFollowsTheReadTimeout` 钉住 `readTimeout`；`TestClientStreamRecvReportsUnavailableWhenTheCallContextEnds` 与 `TestClientStreamRecvReportsCanceledWhenTheSlotIsClosed` 分别钉住 `recv` 的两个出口。
- 注释同步：`channel` 的 `Send`/`Close`，`client` 的 `Close`/`Ping`/`Invoke`/`RoundTrip`/`createStream`/`WithTimeout`/`Options.Timeout`，`driver` 的 `defaultTimeout`，`stream` 的 `CallOptions.apply`，全部按当前实现重写。
