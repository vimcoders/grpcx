# v1.12.39

注释与测试补齐的一版，顺带把 keepalive 对齐到 `defaultTimeout`。没有新的失败语义，`transport` 的收发路径与 v1.12.38 一致；变的是空闲连接的探测节奏、流超时的默认值，以及两条此前没有用例钉住的分支。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/driver.go` `defaultKeepalive` | 由 `10 * time.Second` 改为 `defaultTimeout`（3s），连带 `defaultReadTimeout` 由 30s 降到 9s |
| `transport/client.go` `DialContext` | 接收循环改用 `context.WithoutCancel(ctx)`，删掉 `//nolint:gosec` |
| `transport/channel.go` `Send` | 注释写明 `bufsize <= 0` 就是默认值 |
| `transport/client.go` `WithBufSize`、`Keepalive` | 注释写明「默认 0，攒批是 opt-in」；`Keepalive` 改为「固定值，不派生自调用方超时」 |
| 根 `client.go` `Close` | 读超时描述由「30s」改为「three keepalive periods」 |
| `transport/channel_test.go`、`transport/stream_test.go` | 新增两条用例，见「测试」 |
| `transport/options_test.go` `TestOptionsAccessors` | keepalive 断言改为引用 `defaultKeepalive`，不再写死 10s |

## 行为变化

- **keepalive 3s**：`Options.Keepalive()` 从 10s 变 3s，`roundrobin` 的 ticker 同步变密，空闲连接每 3s 打一次 ping。理由是 grpcx 自己发 ping，不受 gRPC 客户端 keepalive 10s 下限的约束。
- **流超时 30s → 9s**：`defaultReadTimeout` 是 `3 * defaultKeepalive`，跟着降到 9s。它同时是 `createStream` 的流上下文超时，所以单次 unary 的上限从 30s 降到 9s；也是空闲连接「多久没有帧就判死」的窗口。
- **ping 与读超时仍共用一个值**：ping 超时等于 `readTimeout`（9s），而 ping 间隔是 3s，同一条连接上最多会有三个 ping 在途。`Keepalive` 是串行 `Ping`，一个不响应的后端会把一轮拖到 9s，3s 的 ticker 期间丢两个 tick。这是下面 P1-1 的具体后果，这版没有修。
- **接收循环的 ctx**：`context.WithoutCancel(ctx)` 与原来的 `context.Background()` 对 `Handle` 等价（`Done()` 永不触发），区别只在保留了父 ctx 上的 values，同时不再需要 `//nolint:gosec` 抑制 G118。

## 测试

- 门禁全绿：`gofmt -l .` 空、`go vet ./...` 空、`golangci-lint run` 0 issues、`go test ./... -count=1` **153 通过 0 失败**（Windows，`CGO_ENABLED=0`）。
- 新增 `TestChannelTimerFlushFailureOnlyReachesTheLog`：把一帧攒进缓冲区后断掉对端，`Send` 依然返回 nil；timer flush 失败只写日志并关连接，直到下一次 `Send` 才报错。这条钉住 P1-2 的现状，修了它这条用例必须跟着改。
- 新增 `TestClientStreamHandleDropsASecondReply`：接收槽已占满时 `Handle` 走 `default` 分支，归还 payload 并关流，而不是把接收循环卡住。
- 云主机补跑竞态：在 `c3fa2a7` 的 clone 上追加同一组用例，`go test -race ./...` 全包通过，`go test -race ./transport -count=5` 通过（Ubuntu 22.04.5，Go 1.23.0 + `GOTOOLCHAIN=auto`）。`transport` 的收发实现与 v1.12.38 完全一致，所以这份 race 结果对本版有效。

## 已知问题（未解决）

| 编号 | 位置 | 现象 | 影响 |
| --- | --- | --- | --- |
| P1-1 | `transport/driver.go` `defaultReadTimeout` | 一个常量同时当调用上限、连接空闲判定、ping 超时，三个约束方向相反 | 9s 作读超时远大于 3s keepalive 没问题，作 ping 超时却大于 ping 间隔，坏后端上 ping 会在途堆积，串行的 `Keepalive` 把一轮拖长 |
| P1-2 | `transport/channel.go` `push` | timer flush 失败只记 `slog.Debug`，该次 `Send` 早已返回 nil | 攒批模式下最后一批帧的失败没有任何调用方听到，只能靠关连接让对端感知 |
| P1-3 | `transport/stream.go` `recv` | `ctx.Done()` 一律报 `Unavailable` | 调用方自己 cancel 也拿不到 `Canceled`，`Canceled` 分支成了死代码，按码分流的上层无法区分「自己放弃」和「连接坏了」 |
| P2-1 | `transport/client.go` `RoundTrip` | 返回的 `resp.Payload` 是池缓冲，`putmbuf` 是包内私有 | 外部无法归还 |
