# v1.12.40

keepalive 从常量变成配置项的一版。**默认值一个都没变**：不传 `WithKeepalive` 时，行为与 v1.12.39 完全一致。变的是两个旋钮之间的关系——谁跟谁走、谁优先。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/client.go` `Options` | 新增 `keepalive time.Duration` 与 `readTimeoutSet bool` 两个字段 |
| `transport/client.go` `WithKeepalive` | 新增选项：设置 ping 周期，`<= 0` 落回 `defaultKeepalive` |
| `transport/client.go` `WithReadTimeout` | 显式正数记录 `readTimeoutSet`；`<= 0` 落回 `defaultReadTimeout` 并清除标记 |
| `transport/client.go` `Keepalive()` | 由返回常量改为返回 `o.keepalive` |
| `transport/client.go` `DefaultOptions` | 填 `keepalive: defaultKeepalive` |
| `transport/options_test.go` | 新增三条用例，见「测试」 |

## 行为变化

- **默认不变**：`Keepalive()` 仍是 3s，`readTimeout` 仍是 9s，`readTimeoutSet` 为 false。没有调用 `WithKeepalive` 的程序与 v1.12.39 逐字节同行为。
- **read timeout 跟随 ping 周期**：读超时是「多久没有帧就判死」的窗口，必须大于 ping 间隔，否则空闲连接会在两次 ping 之间被拆掉。所以 `WithKeepalive(10s)` 会把 `readTimeout` 一起挪到 30s（3 个周期），这也是默认值本身的比例。
- **显式设置优先，与顺序无关**：调过 `WithReadTimeout` 的话，`readTimeout` 保持你给的值——先写 `WithKeepalive` 还是先写 `WithReadTimeout` 都一样。
- **`WithReadTimeout(0)` 现在表示「回到默认关系」**：此前它只是 `cmp.Or` 落回默认值，但会让后续 `WithKeepalive` 不再联动；现在它同时清掉 `readTimeoutSet` 标记，两个旋钮回到默认比例。
- **只对客户端有意义**：ping 由 balancer 驱动，服务端不读这个值。

## 测试

- 新增 `TestWithKeepaliveMovesTheReadTimeoutWithIt`：`WithKeepalive(10s)` 后 `Keepalive()` 报 10s、`readTimeout` 跟到 30s。
- 新增 `TestWithKeepaliveLeavesAnExplicitReadTimeoutAlone`：两个子场景覆盖选项顺序的正反两种排列，均保持显式的 5s。
- 新增 `TestWithKeepaliveZeroRestoresBothDefaults`：先 `WithKeepalive(10s)` 再 `WithKeepalive(0)`，两个旋钮一起回默认。
- 门禁全绿：`gofmt -l .` 空、`go vet ./...` 空、`golangci-lint run` 0 issues、`go test ./... -count=1` **158 通过 0 失败**（Windows，`CGO_ENABLED=0`），`go test ./transport -count=5` 通过。
- 本版没有并发路径上的改动（只改选项求值与注释），因此没有重复云主机 `-race` 验证；v1.12.38 的 race 结果仍覆盖 `transport` 的收发循环。

## 已知问题（未解决）

| 编号 | 位置 | 现象 | 影响 |
| --- | --- | --- | --- |
| P1-1 | `transport/client.go` `Ping` | ping 的超时就是 `readTimeout`，等于 3 个 ping 周期 | 一次 ping 的预算比 ping 间隔还长，坏后端的 ping 会在同一条连接上叠加到 3 个；`balancer` 的 `Keepalive` 串行 ping，一个不响应的后端把一轮拖长，ticker 期间丢两个 tick |
| P1-2 | `transport/channel.go` `push` | timer flush 失败只记 `slog.Debug`，该次 `Send` 早已返回 nil | 攒批模式下最后一批帧的失败没有调用方听到，只能靠关连接让对端感知 |
| P1-3 | `transport/stream.go` `recv` | `ctx.Done()` 一律报 `Unavailable` | 调用方自己 cancel 也拿不到 `Canceled`，`Canceled` 分支成了死代码 |
| P2-1 | `transport/client.go` `RoundTrip` | 返回的 `resp.Payload` 是池缓冲，`putmbuf` 是包内私有 | 外部无法归还 |
