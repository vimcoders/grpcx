# v1.12.41

撤回 v1.12.40 的接口层改动。那一版新增的 `WithKeepalive` 选项、`readTimeoutSet` 记账字段和 `WithReadTimeout` 的分支改写全部移除，只留 `Options.keepalive` 字段本身。行为回到 v1.12.39。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/client.go` `WithKeepalive` | 删除整个选项，连同其注释 |
| `transport/client.go` `Options.readTimeoutSet` | 删除字段 |
| `transport/client.go` `WithReadTimeout` | 恢复为 `cmp.Or(d, defaultReadTimeout)` 一行，注释回到「3*keepalive」 |
| `transport/client.go` `Keepalive()` | 注释回到「fixed defaultKeepalive」；实现仍是 `return o.keepalive` |
| `transport/options_test.go` | 删除 `WithKeepalive*` 三条用例 |

## 行为变化

- **与 v1.12.39 等价**：`Options` 多了 `keepalive time.Duration` 一个字段，`DefaultOptions()` 填 `defaultKeepalive`，`Keepalive()` 读这个字段。没有设置入口，值恒为 `defaultKeepalive`（3s），所以对外可见的行为和 v1.12.39 完全一致。
- **两类参数的耦合没有新增**：读超时仍固定为 `defaultReadTimeout`（9s），不随 keepalive 变化。想调 ping 周期，目前只能改包内常量。
- **负值处理回到旧路径**：`WithReadTimeout` 恢复 `cmp.Or`，与 v1.12.39 相同；v1.12.40 里「负数也落回默认」的那次顺手改动一并撤销。

## 测试

- 门禁全绿：`gofmt -l .` 空、`go vet ./...` 空、`golangci-lint run` 0 issues、`go test ./... -count=1` **153 通过 0 失败**（Windows，`CGO_ENABLED=0`）。
- 用例数与 v1.12.39 相同：v1.12.40 新增的三条随选项一起删除。`TestOptionsAccessors` 仍按 `defaultKeepalive` 断言，字段化之后依然成立。

## 已知问题（未解决）

| 编号 | 位置 | 现象 | 影响 |
| --- | --- | --- | --- |
| P1-1 | `transport/client.go` `Ping` | ping 的超时就是 `readTimeout`，等于 3 个 ping 周期 | 一次 ping 的预算比 ping 间隔还长，坏后端的 ping 会在同一条连接上叠加到 3 个；`balancer` 的 `Keepalive` 串行 ping，一个不响应的后端把一轮拖长，ticker 期间丢两个 tick |
| P1-2 | `transport/channel.go` `push` | timer flush 失败只记 `slog.Debug`，该次 `Send` 早已返回 nil | 攒批模式下最后一批帧的失败没有调用方听到，只能靠关连接让对端感知 |
| P1-3 | `transport/stream.go` `recv` | `ctx.Done()` 一律报 `Unavailable` | 调用方自己 cancel 也拿不到 `Canceled`，`Canceled` 分支成了死代码 |
| P2-1 | `transport/client.go` `RoundTrip` | 返回的 `resp.Payload` 是池缓冲，`putmbuf` 是包内私有 | 外部无法归还 |
