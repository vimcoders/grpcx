# v1.12.43

`clientStream` 的收口换了归属：`Close` 成为唯一的清理入口，`CloseSend` 只负责摘表。这一版同时把 `transport` 里跟着失效的注释与断言一并对齐，状态检查、vet、lint、全量测试全绿。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/stream.go` `CloseSend` | `deleteStream` 移出 `sync.Once`，每次调用都摘表，随后交给 `Close` 收口 |
| `transport/stream.go` `Close` | `cancel()` 与 `close(s.c)` 收进同一个 `sync.Once`，第二次 `Close` 是 no-op |
| `transport/stream.go` `recv` | 注释重写：接收槽由 `Close` 关闭，`Canceled` 分支不再是死代码 |
| `transport/client.go` `Close` | 注释改写：在途调用被 `s.Close()` 唤醒，code 取 `select` 命中的那一路 |
| `transport/client_test.go` `TestCloseWakesAnInFlightCall`、`TestCloseClosesTheConnectionOnceAndRefusesNewStreams` | 断言从「必须是 `Unavailable`」放开为 `Unavailable` 或 `Canceled` |
| `transport/stream_test.go` | `TestClientStreamCloseSendIsIdempotent` → `TestClientStreamCloseSendDeregistersTheStream`，钉单次 `CloseSend` |

## 行为变化

- **`Close` 之后在途调用的 code 不唯一**：`Close` 同时 cancel context 并关闭接收槽，两个 `select` 分支同时就绪，命中哪个是随机的。300 次采样为 160 `Unavailable` / 140 `Canceled`。
- **`Close` 幂等**：这段清理落在 `sync.Once` 内，两次 `Close` 只有一次 `cancel` + `close`。
- **`CloseSend` 每次都摘表**：不再受 `Once` 保护，调两次会 `delete(c.streams, id)` 两次；单次调用行为不变——摘表一次、结束上下文。
- **接收槽真的会被关闭**：`recv` 的 `Canceled` 分支从死代码变成可达路径。

## 测试

- 门禁：`gofmt -l .` 空、`go vet ./...` 空、`golangci-lint run` 0 issues、`go test ./... -count=1` **158 通过 0 失败 0 panic**。
- `transport` 包 `-count=3`，255 次执行全过，两条放宽后的断言不抖。
- 两条用例改成「`Unavailable` 或 `Canceled`」是跟随实现，不是测试松动：`Close` 一次 arm 两个唤醒源，测试只能钉「调用返回」，钉不住某一个 code。
