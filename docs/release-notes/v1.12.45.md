# v1.12.45

`Handle` 的交接不再看调用状态：槽空就交，槽满才退。这一版把这个取舍写进实现与注释，并把迟到的 payload 归属如实记成「必然不归还」。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/stream.go` `Handle` | `select` 去掉 `<-ctx.Done()`、`<-s.ctx.Done()` 两条分支，只剩 `case s.c <- response` 与 `default` |
| `transport/stream.go` `Handle` 注释 | 按新实现重写：交接不参考调用状态，空槽即收，只有槽已占用才归还 |

## 行为变化

- **投递只看槽是否为空**：调用方已走（ctx 结束）不再影响交接，空槽照收。`Close` 之后到达的回复依旧不会让发送方 panic——这一点与 v1.12.44 一致。
- **`default` 分支不可达**：槽容量 1，一次调用对一条流只交付一个 response，所以「槽已满」永不成立，`putmbuf` 与 `s.Close()` 在正常路径上都不会执行。
- **迟到的 payload 必定留在槽里**：不再有「ctx 结束时顺手归还」的偶然出口，这份 frame buffer 要等 `clientStream` 整体被 GC 才回收。不是增长型泄漏，代价是 `sync.Pool` 少一次复用、多一次分配。
- **`Handle` 的 `ctx` 参数仍在签名里**：`client.Handle` 传的是 `context.WithoutCancel`，当前实现不再消费它，保留为接口形状。
