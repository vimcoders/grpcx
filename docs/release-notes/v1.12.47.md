# v1.12.47

本版没有一行代码改动：`main` 仍停在 `a2c1ca5`，与 v1.12.46 是同一个 commit。变化的只有 tag 本身——从自带 tagger、但无法验证的 annotated tag，换成带 SSH 签名的 signed tag，发布身份第一次具备了可验证性。

## 改动

| 位置 | 处理 |
| --- | --- |
| `v1.12.47` tag | annotated → signed，算法 `ssh-ed25519`，密钥指纹 `SHA256:fiiHIWvbugEObVWipEHgSAs1WZPXEBUHkNvDjor1nZw` |
| GitHub 账户 | 该公钥以 **Signing Key** 类型登记（title `grpcx signing`） |
| 代码 / 测试 / 文档 | 零改动，全部沿用 v1.12.46（同一 commit `a2c1ca5`） |

tag 对象从 137 字节（5 行）变成 432 字节（11 行），多出来的部分是 `-----BEGIN SSH SIGNATURE-----` 块：它记录密钥算法、命名空间 `git`，以及 tag 对象全部字节的 sha512 摘要。

## 为什么值得换

annotated tag 的 `tagger` 行只是一句自述，姓名和邮箱随手就能填成任何人的名字，页面上和真作者长得一模一样。签名把 tag 对象的每一个字节——`object <commit sha>`、`tag` 名、`tagger` 行、message——全部纳入校验范围，改动任意一处验签即失败。

这正是它实际防的东西：**tag 的指向被静默替换**。有人 force push 把 tag 指到别的 commit，签名块不变而 payload 已变，GitHub 的 verification 会从 `valid` 变成失败；反过来，删掉签名再推一个同名 tag，徽标会消失——篡改不再"看起来正常"。

## 验证

- 本地：`git tag -v v1.12.47` 输出 `Good "git" signature for vimcoders@gmail.com with ED25519 key SHA256:fiiHIWv…`。这一步需要 `gpg.ssh.allowedSignersFile` 提供信任锚，仓库目前尚未附带该文件，clone 下来的人须自备。
- GitHub：`GET /repos/vimcoders/grpcx/git/tags/c7fff32c…` 返回 `verified = true`、`reason = valid`、`verified_at = 2026-11-26T16:49:56Z`。
- tag SHA：本地与远端一致，均为 `c7fff32c69a243a4f386dcb4c44facdd100e3000`。
- 门禁：未重跑。代码与 v1.12.46 是同一条 commit，沿用该版结果（160 通过 / 0 失败，`transport` 包 `-count=3` 共 261 次全过）。

## 它管什么、不管什么

管：tag 是否被替换、指向是否被改写，以及事后能不能拿出来核对。

不管：账户被控之后的一切。攻击者拿到账户写权限，可以自己加一把 Signing Key，他打的 tag 照样显示 Verified；也能删公钥、删 tag、force push `main`、改 CI。签名体系的可信上限就是账户安全的上限，本版只把这条链路的下限补齐，剩下的仍在 2FA、分支保护和 token 权限那边。
