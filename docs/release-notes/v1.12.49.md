# v1.12.49

本版不碰运行时路径：没有一行行为改动。改的是对外 API 的表述，和注释里已经说错的话。`CallOption` 从 `transport` 提到根包对外，另外四处注释与实现脱节，逐条改正。

## 改动

| 位置 | 处理 |
| --- | --- |
| `client.go` | 新增 `type CallOption = transport.CallOption`，`ClientConnInterface.RoundTrip` 与实现改用别名；只转发字节的调用方不必再 import `transport` |
| `transport/stream.go` `apply` | 原文只写 "Invoke folds the caller's context deadline into the header"，v1.12.48 之后 `RoundTrip` 也折叠，补上 |
| `transport/stream.go` `CallOptions` | 原文说每个非零字段覆盖，但 `Metadatas` 是累加；点明这是唯一的例外 |
| `transport/client.go` `WithWriteTimeout` | 默认值误写为 `defaultTimeout`，实际是 `defaultWriteTimeout`——两者都是 1s，但常量不是同一个 |
| `transport/client.go` `RoundTrip` | 池注释原文"每个超过 256B 的回复都拿 4KB"，5000B 实测拿 16KB；改成"下一档是 4KB" |
| `client_test.go` | `recordingRT.RoundTrip` 用 `...CallOption`，别名在编译期即被验证 |

## 为什么值得单独发一版

注释错得越像真的，越容易被当成事实抄进下游的封装。这一版修正的四处，全部是 v1.12.48 的接口改造之后才变味的：`apply` 的折叠主语少了一个、`Metadatas` 的累加被笼统的"覆盖"盖住、`RoundTrip` 的池边界口径比实测窄了一档。它们不改变任何行为，但会让读代码的人建立错的模型。
