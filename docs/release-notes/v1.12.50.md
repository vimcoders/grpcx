# v1.12.50

产品代码一行未动。这一版补两件看不见的东西：`CallOptions` 也搬到根包对外，以及一条原本不存在的断言——根包 `RoundTrip` 到底有没有把 payload 和 options 原样交给后端。

## 改动

| 位置 | 处理 |
| --- | --- |
| `client.go` | 新增 `type CallOptions = transport.CallOptions`；`CallOption` 的注释改为指向它——接口在根包，值也在根包，定义仍在 transport |
| `client_test.go` `recordingRT` | 记录 `RoundTrip` 收到的 payload 与选项个数（`atomic.Pointer[[]byte]` / `atomic.Int32`）；此前它把这两个入参直接丢掉 |
| `client_test.go` `TestRoundTripPicksWithoutNamingAMethod` | 加两条断言：后端收到的字节等于 `body`、选项个数等于 1；构造 header 改用根包别名 `&CallOptions{}` |
| `transport/client_test.go` `TestRoundTripSmallReplyFreesAsANoop` | 注释原说"没进池的档位"，真实判据是容量低于 1KB 池化阈值；改成按判据说 |

## 为什么那条断言重要

改之前的测试对"透传"是盲的：`recordingRT.RoundTrip` 忽略入参，只回一个固定的 `reply`。如果实现写成 `rt.RoundTrip(ctx, nil, opts...)`、把 payload 和 options 一起丢掉，全部测试仍然是绿的——而这恰恰是根包这一层唯一的职责。新断言把洞堵上：payload 要原样到后端，选项个数要原样到后端。

小 reply 那条同理：它断言的结论一直没错（返回 `SliceBuffer`、`Free` 之后仍可读），但解释错了。决定它是不是 `SliceBuffer` 的不是"池的最小档 256B"，而是 `IsBelowBufferPoolingThreshold(cap)`，即容量是否低于 1KB。注释现在按判据写，不按结论倒推。
