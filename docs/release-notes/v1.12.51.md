# v1.12.51

P1-2 收口：批处理定时器的写失败不再只落在日志里，改为关闭连接。

## 改动

| 位置 | 处理 |
| --- | --- |
| `transport/channel.go` `push` | 失败分支由 `slog.Debug(...)` 改为 `_ = x.Conn.Close()`，并删除 `log/slog` import |
| `transport/channel.go` 注释 | `push` 与 `Send` 的注释从"错误只进日志""无声丢失"改为新契约：关闭连接是留给等待者的唯一信号 |
| `transport/channel_test.go` | `TestChannelTimerFlushFailureOnlyReachesTheLog` 改名 `TestChannelTimerFlushFailureClosesTheConnection`，并补一条此前没有的断言：flush 失败后 `Recv()` 必须立刻返回错误 |

## 为什么改

timer flush 是唯一没有调用者听到的写失败。那批帧排队时 `Send` 已经返回 nil，失败发生时没有调用方在等；原实现把它写进 `slog.Debug`，除此之外什么都没发生——连接照旧可用（实际上已经在丢帧），等响应的调用还得熬满 9 秒读超时。

现在失败即关闭：

- 等响应的调用在关闭的连接上立刻拿到错误，不再等满读超时；
- 下一次 `Send` 在 `SetWriteDeadline` 上失败，返回 `ErrClosed` 与 `codes.Unavailable` 的组合。

持 `x.Lock()` 时关闭的是嵌入的 `net.Conn`，不是 `channel.Close()`，不重入 `sync.Mutex`；`time.AfterFunc` 是一次性的，不会自重复。

## 边界：承诺什么、不承诺什么

**P1-2 到此关闭。** 原本的缺陷是「失败只进日志、没有任何一方知道」；现在失败有三处可观测：等响应的调用在关闭的连接上立刻拿到错误，下一次 `Send` 在 `SetWriteDeadline` 上立刻失败，连接池里的连接处于关闭状态会被剔除。静默没有了。

不承诺的是回执：`Send` 返回 nil 的语义是帧已进队列（收下了），不是已送达。那批帧在之后的定时器 flush 里丢掉时，结果无法回传给一个早已返回的调用——除非让 `Send` 同步等 flush，那也就放弃了 `bufsize` 批处理。这是当初选择批处理的固有代价，不属于本次修复的缺口。

另外删掉了日志：写失败的原始原因（EPIPE / RST）不再留痕。若需要，可在 channel 上记一个 `lastErr`，让下一次 `Send` 把原始错误一并 `errors.Join` 进 `codes.Unavailable`。
