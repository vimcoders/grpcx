# v1.12.54

`Codec` 接口从「返回裸 `[]byte`」改成 Buffer 化，帧层去掉 protobuf 包装。目标是
1MB 报文的分配：改完之后单次 `Marshal` 在池命中时 0 alloc，首次也只有 1 alloc。

**破坏性变更**：`transport.Codec` 的 `Marshal` / `Unmarshal` 签名变了，自定义 codec
必须跟着改。

## 接口

| | 旧 | 新 |
| --- | --- | --- |
| `Marshal` | `Marshal(any) ([]byte, error)` | `Marshal(any) (Buffer, error)` |
| `Unmarshal` | `Unmarshal([]byte, any) error` | `Unmarshal(Buffer, any) error` |

## 改动

| commit | 范围 | 内容 |
| --- | --- | --- |
| `3a2019a` | 20 个文件，1854+/2917- | Codec Buffer 化，帧层换 CallOptions 头，重写全部测试 |

- `defaultCodec`：`proto.Message` 走 `getmbuf(proto.Size)` + `MarshalAppend`
  （`UseCachedSize`），返回池缓冲；非 proto 交给内置 `encoding.Codec`，返回
  `emptyBuffer`（`Free` 是空操作）。
- 头帧改为直接编码 `CallOptions`，不再包 `api.Request` / `api.Response`。
- 服务端 `WithServerBufSize` 据此在 `defaultCodec` 与 `codec` 之间二选一。
- `bench/grpcx` 的批量阈值从 `GOMAXPROCS` 改成 `GOMAXPROCS*1024` 字节 —— 原值
  当字节阈值用几乎从不触发批量。

## 1MB 分配

i5-14600KF，`-benchmem -benchtime=300x`，payload 1MB：

| 路径 | ns/op | B/op | allocs |
| --- | --- | --- | --- |
| `getmbuf(1MB)` + `Free` | 12837 | 3528 | 1 |
| `defaultCodec.Marshal` | 108682 | 3579 | 2 |
| `codec.Marshal` | 161433 | 1056813 | 2 |
| `proto.Marshal` | 155805 | 1056774 | 1 |
| 预分配 `MarshalAppend` | 51297 | 3522 | **0** |

3.5KB 是首次 1MB 分摊到 300 次的结果，池命中后归零。相对 `proto.Marshal`
分配字节降到 1/295，耗时快约 1.4 倍。

`codec`（非 proto 池化路径）与标准库持平甚至略差 —— 2 alloc 对 1 alloc。账在
1MB 帧上本来就白付：`WithBufSize` 上限 16384 字节，1MB 帧一进 `Send` 就超阈值
当场同步写，`codec` 只替几 KB 小帧排队。

## 测试

按当前实现重写 10 个测试文件，2263 行。

| 包 | 覆盖率 |
| --- | --- |
| `transport` | 87.1% |
| 根包 | 84.5% |
| `balancer` | 78.9% |

重写时修掉一个测试缺陷：`TestListenAndServeServesEcho` 在 `-race` 下 10 次挂 7
次。`ListenAndServe` 的 `net.Listen` 在服务端 goroutine 里，而 `balancer.Ping`
吞掉 dial 失败、`Build` 只看 resolve 是否成功 —— 端口还没 bind 时拿到的 client
是空池，`Pick` 直接回 `Unavailable`。改成 `waitForPort` 探测端口可连再 Dial，并把
`TestListenAndServeStopsOnCancel` 里跑在 goroutine 中的 `freeAddr(t)` 挪回主线程
（`t.Fatalf` 不能在测试 goroutine 外调用）。

## 首跑 CI 的修正

发版后 CI 首跑 `-race`，`TestWithServerBufSizeChoosesTheCodec/negative` 失败：

```
options_test.go:165: bufsize = 0, want -1 stored as given
```

断言还停在「负值仍装 `&codec{}`」的旧现状，而 `WithServerBufSize` 早已对负值早退
（`if n < 0 { return }`，默认阈值 0 与 `defaultCodec` 都保留）。断言已改成
「`bufsize` 保持默认 0、`Codec` 是 `*defaultCodec`」，随 `test(transport)` 修正提交。
上一版 note 里把这条记为「已知未修」是误判，代码本身没有这个缺陷。
