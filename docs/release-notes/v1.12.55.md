# v1.12.55

`StreamID` 收口在 transport 一侧：`CallOption` 不再能改它。

## 改动

| commit | 范围 | 内容 |
| --- | --- | --- |
| `df79315` | 3 个文件，41+/10- | StreamID 改为「头里已有 id 优先」，同步注释，加一条测试 |

`apply` 里这一行从 `cmp.Or(c.StreamID, opts.StreamID)` 改成
`cmp.Or(opts.StreamID, c.StreamID)`。

`createStream` 分配的 id 从 1 起，所以 `c.StreamID` 只在头里为 0 时才生效，而那条路径
在 `RoundTrip` 里不存在。指向别的流的帧在本连接的流表里查不到，调用必然
`Unavailable` —— 覆盖只会把一次正常调用变成失败。

服务端不受影响：`Handle` 与 `empty.Handle` 都从零值头开始 apply，`options.StreamID`
仍能填进去，`sender.send` 拼回包时同理。

## 注释同步

| 位置 | 原来写的 | 现在 |
| --- | --- | --- |
| `RoundTrip` | 非零 StreamID 替换已分配的，调用方可以把帧路由到另一条流 | 已分配的 id 保留，指向别的流会查不到流表 |
| `CallOptions` | 每个非零字段覆盖头里对应项 | 补上 StreamID 是反例、Metadatas 是累加 |
| `apply` | 统一「c 的非零字段覆盖」 | 补上 StreamID 反向：头里已有就保留 |
