# v1.12.57

`Codec` 的形态统一为指针，装配点收口到 `Options.newCodec` 一个入口。无行为变化。

## 改动

| 文件 | 内容 |
| --- | --- |
| `transport/client.go` | `Options.newCodec` 返回 `&emptyCodec{}` / `&defaultCodec{}`，不再返回值 |
| `transport/server.go` | `DefaultServerOptions` 由手写 `&defaultCodec{opt.ecodec}` 改为 `opt.newCodec()` |
| `transport/client_test.go` | `TestDialContextChoosesTheCodec` 断言对齐指针 |
| `transport/options_test.go` | 三处测试共 8 个断言对齐指针，`negative` 分支注释重写 |
| `transport/stream_test.go` | `sender` 夹具统一用 `&emptyCodec{}` |

## 为什么

v1.12.56 里 `Codec` 有两种形态：`DefaultServerOptions` 装的是 `*defaultCodec`，`newCodec` 返回的是 `defaultCodec`。同一个字段两种形态，`options_test` 被迫写两套断言，`negative` 分支还专门加了一段注释来解释这个分裂。

现在 `newCodec` 恒返回指针，四个装配点全部走它：

```
transport/client.go:213   DialContext        opt.newCodec()
transport/server.go:53    DefaultServerOptions opt.newCodec()
transport/server.go:93    WithServerCodec    opt.newCodec()
transport/server.go:137   WithServerBufSize  opt.newCodec()
```

阈值是唯一的开关，形态是唯一的值。以后改默认阈值，也不会有第二个地方偷偷装配出另一种形态。

## 兼容性

无行为变化。`emptyCodec` 与 `defaultCodec` 的方法都是值接收者，指针调用自动解引用，接口照样满足；`DefaultServerOptions` 每次调用仍分配新的 Codec，每个 server 依然独享。

## 测试

- 断言全部改成 `*defaultCodec` / `*emptyCodec`，守卫的仍然是 `bufsize` 的 0 边界：`0` 与负值走池化，`1` 走不池化。
- `grep 'Codec\.\((defaultCodec|emptyCodec)\)'` 无命中，值形态已清零。
