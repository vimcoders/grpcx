## 修复

### 非法 Metadata 返回 InvalidArgument

新增：

```go
func ParsePairs(kv ...string) (MD, error)
```

奇数个 key/value 输入返回 `(nil, error)`，不再 panic。服务端在读完请求 payload 后使用 `ParsePairs`，解析失败时回复 `codes.InvalidArgument`，而不是把错误抛到连接 goroutine。

请求级错误通过响应头发回，连接保持帧对齐，后续调用可以继续复用同一连接。每调用的 `recover` 也前移到了 Metadata 解析之前，作为意外 panic 的兜底。

兼容性：原 `Pairs` 和 `AppendToContext` 的签名均未改变。`Pairs` 仍会对奇数输入 panic，但 panic 值由 string 变为 error，错误文案调整为 `metadata: odd number of key/value inputs: N`。

### defaultCodec 编解码对称

`defaultCodec.Unmarshal` 现在与 `Marshal` 使用同一套类型分支：

| 类型 | Marshal | Unmarshal |
| --- | --- | --- |
| `proto.Message` | protobuf + 池 Buffer | `proto.Unmarshal` |
| 非 proto | 自定义 `ecodec.Marshal` | 自定义 `ecodec.Unmarshal` |

此前 proto 会由 protobuf 编码，却被交给自定义 Codec 解码；默认关闭批量时，自定义 Codec 无法可靠处理 proto 消息。

`emptyCodec` 未改：开启批量时，所有类型仍交给 `ecodec`。

### 状态消息不再嵌套

服务端原先把 `err.Error()` 放进响应的 `Desc`，客户端再用它构造 `status.Error`，会得到：

```text
rpc error: code = InvalidArgument desc = rpc error: code = InvalidArgument desc = ...
```

现在服务端只传 `status.Convert(err).Message()`，客户端收到的是：

```text
rpc error: code = InvalidArgument desc = test: handler failed
```

状态码不变，普通非 status 错误的原始消息仍会保留。
